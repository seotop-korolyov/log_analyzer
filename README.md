# Log Analyzer

A Python command-line tool for analyzing application log files.

The script parses structured application logs, calculates statistics for different log levels, identifies the most frequent messages and services, and supports filtering by service, log level, and time range.

This project was created as practical Python and DevOps practice focused on log analysis, troubleshooting, command-line tools, and processing real-world text data.

## Features

The analyzer can:

* Parse structured application logs
* Count `ERROR`, `WARNING`, `INFO`, and `DEBUG` entries
* Calculate the percentage of each log level
* Find the most frequent log messages
* Find services producing the most log entries
* Filter logs by service
* Filter logs by log level
* Filter logs by start and end time
* Detect malformed log lines
* Validate command-line arguments
* Handle missing files and permission errors
* Control the number of results displayed with `--top`

## Expected Log Format

The analyzer expects log entries in this format:

```text
YYYY-MM-DD HH:MM:SS LEVEL [service] pid=NUMBER message
```

For example:

```text
2026-09-29 08:05:55 ERROR [auth] pid=4027 Upstream service timeout
```

From this line, the analyzer extracts:

```text
Timestamp: 2026-09-29 08:05:55
Level:     ERROR
Service:   auth
Message:   Upstream service timeout
```

## Usage

Basic usage:

```bash
python3 log_analyzer.py <log_file>
```

For example:

```bash
python3 log_analyzer.py devops_application.log
```

You can also make the script executable:

```bash
chmod +x log_analyzer.py
./log_analyzer.py devops_application.log
```

## Command-Line Options

### Show a specific number of top results

By default, the analyzer displays the top 5 messages and services.

```bash
python3 log_analyzer.py devops_application.log --top 10
```

Short form:

```bash
python3 log_analyzer.py devops_application.log -t 10
```

The value must be a positive integer.

### Filter by service

Analyze only entries produced by a particular service:

```bash
python3 log_analyzer.py devops_application.log --service api
```

Short form:

```bash
python3 log_analyzer.py devops_application.log -s api
```

### Filter by log level

Available levels are:

```text
error
warning
info
debug
```

Example:

```bash
python3 log_analyzer.py devops_application.log --level error
```

Short form:

```bash
python3 log_analyzer.py devops_application.log -l error
```

### Filter by start time

Analyze entries from a specified timestamp:

```bash
python3 log_analyzer.py devops_application.log \
  --since "2026-09-29 08:30:00"
```

### Filter by end time

Analyze entries up to a specified timestamp:

```bash
python3 log_analyzer.py devops_application.log \
  --until "2026-09-29 09:00:00"
```

### Analyze a specific time range

The filters can be combined:

```bash
python3 log_analyzer.py devops_application.log \
  --since "2026-09-29 08:30:00" \
  --until "2026-09-29 09:00:00"
```

The analyzer validates the timestamps and checks that `--since` is not later than `--until`.

## Combining Filters

Command-line options can be combined.

For example, to find the top 3 errors generated by the `api` service within a specific period:

```bash
python3 log_analyzer.py devops_application.log \
  --service api \
  --level error \
  --top 3 \
  --since "2026-09-29 08:00:00" \
  --until "2026-09-29 10:00:00"
```

This makes it possible to narrow a large log file down to the entries relevant to a particular investigation.

## Malformed Log Handling

Lines that do not match the expected structure or contain an invalid timestamp are treated as malformed.

Instead of stopping the entire analysis, the program skips those entries and reports their number:

```text
Malformed lines: 2
```

This allows the analyzer to continue processing the rest of the log file.

## Example Investigation

Suppose an application is experiencing database problems.

Instead of manually searching through the entire log file, the analyzer can display only errors:

```bash
python3 log_analyzer.py devops_application.log --level error
```

Or errors from one service:

```bash
python3 log_analyzer.py devops_application.log \
  --level error \
  --service api
```

The resulting statistics help identify which error messages occur most frequently and which services generate them.
